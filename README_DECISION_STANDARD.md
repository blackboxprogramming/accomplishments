# README decision standard

Every BlackRoad repository README must answer these questions near the top, in plain language, with links to evidence where available.

## Why at all?
Who has the problem? What is the cost or risk of leaving it unsolved? When is doing nothing reasonable? Avoid inventing demand.

## Why now?
What has changed that makes action timely? State real deadlines, dependencies, costs of delay, or opportunities. If there is no demonstrated urgency, say so. Never manufacture urgency.

## Why this?
What does this repository deliver? Why choose it over doing nothing, existing tools, competitors, or building internally? Explain the trade-offs, limitations, ownership, permission boundaries, and reversibility.

## Prove it
Link to reproducible tests, working demonstrations, source, receipts, benchmarks, and observed results. Distinguish verified claims from planned features and hypotheses. Specify environment, date, and scope. Never add overlapping test counts or generalize narrow benchmarks.

## What next?
Give a minimal, safe path to evaluate the project, with prerequisites, verification steps, and a clear exit or rollback route.

### Review checklist
- [ ] Why at all answered
- [ ] Why now answered without manufactured urgency
- [ ] Why this answered with alternatives and trade-offs
- [ ] Proof linked and limitations stated
- [ ] Safe evaluation and rollback documented
- [ ] No unsupported claims, inflated counts, or invented customer outcomes

This is a documentation contract, not evidence that all repositories currently comply. Roll out by auditing existing READMEs, preserving their technical details, and reviewing changes repository by repository. Keep private repositories private and never copy secrets into documentation.
